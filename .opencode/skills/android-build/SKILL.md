# SAFSHET — Android Build and Project Maintenance

Назначение: правила сборки, проверки конфигурации и сопровождения Android-проекта SAFSHET.

## Проект

- Основной проект — Android-модуль `:app`, язык Kotlin, UI на Jetpack Compose и Material 3.
- Сборка — Gradle Kotlin DSL; используй существующий Gradle Wrapper: `.\gradlew.bat` в Windows, `./gradlew` в Unix.

## Зависимости и версии

- Перед изменением зависимостей проверяй версии и совместимость с текущими настройками проекта.
- Не обновляй версии просто ради обновления; обновление должно быть обусловлено конкретной технической причиной.
- Соблюдай заданные в проекте `minSdk`, `compileSdk`, `targetSdk` и версию Java. Не меняй их без обоснования.
- Следи за согласованностью версий: Compose BOM, версия Kotlin-плагина `org.jetbrains.kotlin.plugin.compose` и версия Android Gradle Plugin должны быть совместимы между собой.

## Проверка сборки

- После изменения кода выполняй подходящую проверку сборки, например `.\gradlew.bat :app:assembleDebug`.
- Если проверка не прошла, укажи точную ошибку и не заявляй об успешной сборке.
- Не утверждай, что сборка успешна, пока результат не подтверждён фактически.

## Ограничения

- Не удаляй файлы, конфигурации и зависимости без проверки их назначения.
- Не добавляй сетевые сервисы, аналитику, телеметрию и облачную синхронизацию без явного требования.
- Не запускай команды, изменяющие Git, не создавай коммиты и не отправляй изменения на сервер без прямого указания пользователя.
- Перед потенциально разрушающими операциями сначала покажи план и запроси подтверждение.

## Отчёт

- В отчёте указывай изменённые файлы, выполненные проверки и их фактические результаты.
- Чётко различай подтверждённые факты и предположения.
